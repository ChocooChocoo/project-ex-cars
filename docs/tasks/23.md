# Objective
## Transactions Page Redesign Using Template Dashboard Components

---

## Role
You are a frontend UI/UX developer specializing in template-driven component reuse and data integration. Approach this objective with a focus on exact design replication, component fidelity, and real-time data binding without visual deviation.

---

## Description
The objective is to redesign the Transactions page located at http://localhost:3000/{users}/transactions by replacing two major sections with template components from the dashboard template library. The existing table on the Transactions page must be replaced with the exact customers table design from the Default template dashboard, preserving the search box, filter dropdowns, pagination controls, table layout, styling, and all columns without modification — only the data content and the Action column's context menu items may be adapted. Additionally, the KPI cards above the table must be replaced with the exact KPI card design from the Analytics template dashboard, such as the Unique Visitors and Sessions cards, with all placeholder and hardcoded data replaced by real database values. All work must be executed using multiple agents and skills located in the .opencode folder.

---

## Primary Objective
Redesign the Transactions page by faithfully replicating the customers table from the Default template dashboard and the KPI cards from the Analytics template dashboard, integrating real database data without altering any component's design, layout, or styling.

---

## Secondary Objectives
- Replicate the customers table from http://localhost:3000/template/dashboard/default with exact design fidelity — preserving search box, filter dropdowns, pagination controls, table layout, styling, and all columns — as the replacement table on the Transactions page.
- Adapt only the table's data bindings and the Action column's context menu items to match the Transactions context, while keeping the three-dots icon (⋮) trigger.
- Replace the existing KPI cards above the table with the exact KPI card design from http://localhost:3000/template/dashboard/analytics, such as Unique Visitors and Sessions cards.
- Replace all placeholder and hardcoded data in the KPI cards with real data from the database.
- Execute all planning and implementation using multiple agents and skills from the .opencode folder.

---

## Success Criteria
- The Transactions page table is visually and structurally identical to the Default template dashboard's customers table, differing only in data content and Action menu items.
- The search box, filter dropdowns, pagination controls, and overall table structure remain unmodified from the template.
- The Action column retains the three-dots icon (⋮) that opens a context menu with transaction-relevant actions.
- The KPI cards above the table are visually and structurally identical to the Analytics template dashboard's KPI cards.
- All KPI card values display real database data with no placeholder or hardcoded content.
- Both components are fully integrated into the Transactions page at http://localhost:3000/{users}/transactions.

---

## Constraints
- The customers table from the Default template must not be redesigned or modified in any way beyond data content and Action menu items.
- The KPI cards from the Analytics template must not be redesigned or modified in any way beyond replacing placeholder data with real database values.
- All tasks must be executed using multiple agents and skills from the .opencode folder.

## Detailed Breakdown

### Table Design Fidelity Requirement
The customers table from the Default template dashboard must be replicated with absolute fidelity. This includes the search box functionality, all filter dropdowns and their options, pagination controls with their exact styling and behavior, the table layout including column widths and alignment, all visual styling including borders, spacing, typography, hover states, and row treatments. The only permitted deviations are the data content populating the rows and the actions available in the Action column's context menu. The three-dots icon (⋮) that triggers the context menu must remain unchanged.

### KPI Cards Design Fidelity Requirement
The KPI cards from the Analytics template dashboard must be replicated with absolute fidelity. This includes the card container styling, icon placement, label typography, value formatting, trend indicators, sparklines or charts if present, spacing, and all visual treatments. The only permitted change is replacing placeholder and hardcoded values with real data from the database. No card structure, styling, or layout may be modified.

### Data Integration Approach
For both the table and KPI cards, identify the exact data shape each template component expects. Map these expectations to the corresponding database tables, fields, or API endpoints that supply the Transactions page's real data. Perform all necessary data transformation, field aliasing, and value formatting at the integration layer without modifying any component's internal rendering logic, markup, or styling.
