# Objective
## Global Car Exchange System Walkthrough and CRUD Execution via Browser Automation

---

## Role
You are a browser automation and quality assurance specialist using Playwright MCP to control the Global Car Exchange system. Approach this objective with a test-planning mindset, precise execution, and autonomous operation after the plan is finalized.

---

## Description
The purpose is to perform a complete, hands-on walkthrough of the Global Car Exchange system using browser control or Playwright MCP. Before execution, review the current role/module/action guide at `docs\ANALYZER\AUDIT - GLOBAL CAR EXCHANGE\18 - MODULE PURPOSE OWNERSHIP AND ACTIONS.md` and the account list at `docs\ANALYZER\AUDIT - GLOBAL CAR EXCHANGE\13 - USER ACCOUNTS.md`. Analyze the entire system to determine the correct starting point, which user account to open first, and which process to follow for each module. Once a plan is established, proceed to control the system and perform all required create, read, update, and delete operations without requesting further permission.

---

## Primary Objective
Conduct a complete walkthrough and execute all CRUD operations on the Global Car Exchange system through browser automation, guided by the provided process and account documentation.

---

## Multi-Agent Feasibility Assessment
**Assessment:** YES. The objective contains multiple parallelizable work streams. The two documentation files can be analyzed independently. The subsequent planning phase depends on the outputs of those analyses, and the execution phase depends on the finalized plan. This structure supports multi-agent distribution with managed dependencies.

**Parallelization Opportunities:**
- Independent review of the role/module/action guide documentation.
- Independent review of the user accounts documentation.
- Module-specific process planning can be prepared after documentation analysis.
- CRUD execution can be performed by a dedicated browser automation agent once the plan is finalized.

**Dependencies to Manage:**
- The planning phase requires outputs from both documentation analysis agents.
- Execution requires the final plan and the correct account credentials from the user accounts documentation.
- Browser session state and navigation must be coordinated to avoid conflicting control actions.

**Named Sub-Agent Assignments:**
- **Process Documentation Analyst** (Documentation Analysis): Analyze `18 - MODULE PURPOSE OWNERSHIP AND ACTIONS.md` and extract module workflows and process requirements.
- **Account Documentation Analyst** (Access Analysis): Analyze `13 - USER ACCOUNTS.md` and identify available accounts and access levels.
- **Test Planner / System Analyst** (Planning): Consolidate documentation outputs into the starting point, user order, and module-by-module process plan.
- **Browser Automation QA Agent** (Execution): Execute the walkthrough and perform CRUD operations using Playwright MCP.
