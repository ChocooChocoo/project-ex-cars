# Objective

## Fix CEO Dashboard Errors, Interaction Bugs, and UI/UX Issues

---

## Role

You are a full-stack software engineer responsible for diagnosing and implementing fixes across the CEO-facing application. Approach this objective with attention to authorization, row-level security, frontend interactions, confirmation flows, responsive layout behavior, and UI/UX consistency.

---

## Description

Resolve the identified errors, broken interactions, layout issues, and UI/UX inconsistencies across the CEO section of the application. Each affected route should behave correctly for the CEO role, including authorization-sensitive actions, form controls, record updates, confirmations, navigation behavior, and page layouts. Preserve the intended functionality of each feature while correcting the reported defects and implementing the specified interface changes. Planning should remain centralized, while implementation work should use multiple sub-agents where tasks can be handled independently.

---

## Primary Objective

Diagnose and implement all listed fixes and UI/UX changes across the CEO application routes so that each reported workflow functions correctly and matches the specified behavior.

---

## Secondary Objectives

* Resolve authorization and row-level security failures affecting CEO workflows.
* Add confirmation steps before specified consequential actions.
* Correct broken form controls, selectors, and update actions.
* Improve specified page layouts by making relevant content full width.
* Correct roadmap creation behavior so it uses the side application drawer.
* Align the Supplier Messages interface with the existing Inquiries page design.
* Use multiple sub-agents for parallel implementation work while keeping planning centralized.

---

## Success Criteria

* The transaction workflow at `/ceo/transactions/abdd42ef-50f3-4815-a4a9-a569b4021b4b` no longer fails with a row-level security policy violation.
* Finance request verification requires confirmation before the verification action proceeds.
* The inspection Summary card is corrected and displayed at full width.
* The CEO can access `/ceo/inquiries` without receiving a `Not authorized` error when the CEO role is intended to have access.
* Assigning an inquiry to the current user requires confirmation before completing the self-assignment.
* Creating a roadmap opens the side application drawer instead of navigating to a new page.
* The employee selector in the Add Compensation Record modal responds and allows the intended employee-selection workflow.
* The Payslip page is displayed at full width.
* The Create Field Case workflow provides usable Case Kind and Assigned Worker selectors instead of the reported authorization message or non-responsive behavior.
* Clicking `Mark Review` on the Reports page successfully updates the relevant report state.
* Publishing or expiring an announcement requires confirmation before the action proceeds.
* Supplier Messages uses the same conversation/interface design as the Inquiries page instead of the current card-based conversation UI.
* All listed implementation items are completed without distributing the planning phase across sub-agents.

---

## Constraints

* Use multiple sub-agents during implementation only.
* Do not use multiple sub-agents for planning.
* Preserve the existing intended feature behavior except where a specific change is explicitly requested.
* For Supplier Messages, use the same exact UI design pattern already used by the Inquiries page rather than introducing a new conversation design.

## Multi-Agent Feasibility Assessment

**Assessment:** YES. The implementation contains multiple distinct work streams across separate CEO routes, including authorization fixes, confirmation flows, layout updates, form-control bugs, navigation behavior, data-update logic, and UI restructuring. Most of these items can be investigated and implemented independently after a single centralized planning pass. Multi-agent distribution should therefore be used for implementation, while planning and final integration remain coordinated centrally as explicitly required.

**Parallelization Opportunities:**

* Investigate and fix transaction row-level security behavior.
* Investigate CEO authorization for Inquiries.
* Implement Finance verification confirmation.
* Implement Inquiries self-assignment confirmation.
* Correct the inspection Summary card layout.
* Fix the payroll employee selector.
* Correct the Payslip full-width layout.
* Diagnose and fix Field Case Kind and Assigned Worker selectors.
* Fix the Reports `Mark Review` update behavior.
* Implement Announcement Publish and Expire confirmations.
* Update roadmap creation to use the side application drawer.
* Rework Supplier Messages to match the Inquiries UI.

**Dependencies to Manage:**

* Complete planning centrally before implementation tasks are distributed.
* Authorization-related fixes should remain consistent with the application's existing role and row-level security model.
* Shared confirmation components or patterns should remain consistent if multiple affected pages use the same implementation.
* Supplier Messages must use the existing Inquiries UI as its design reference, so the relevant Inquiries components and layout should be identified before implementation.
* Final integration should check for conflicts where agents modify shared components, authorization utilities, layout primitives, modal components, or common data-access logic.
* All independently implemented fixes should be validated together after integration to ensure that changes to shared code do not introduce regressions.

**Named Sub-Agent Assignments:**

* **Security & Authorization Agent** (Authorization/RLS Specialist): Diagnose and implement the transaction row-level security fix, the Inquiries authorization fix, and the Field Case role-related Case Kind issue.
* **Workflow Actions Agent** (Frontend Interaction Specialist): Implement Finance verification confirmation, Inquiries self-assignment confirmation, and Announcement Publish/Expire confirmations.
* **Forms Agent** (Form & Component Specialist): Fix the Payroll employee selector and the Field Case Assigned Worker and Case Kind selector behavior.
* **Layout Agent** (Frontend Layout Specialist): Fix the inspection Summary card and make both the Summary card and Payslip page use the requested full-width layouts.
* **Data Actions Agent** (Application State Specialist): Diagnose and fix the Reports `Mark Review` action so the state update persists and is reflected correctly.
* **Roadmap Agent** (Navigation & Drawer Specialist): Replace the new-page roadmap creation flow with the existing side application drawer pattern.
* **Supplier Messages Agent** (UI/UX Implementation Specialist): Replace the Supplier Messages card-based conversation interface with the same design and interaction structure used by the Inquiries page.
