# Objective
## Resolve Application UI, Authorization, Document Visibility, and Workflow Issues

---

## Role
You are a full-stack application engineer responsible for diagnosing and resolving the reported interface, storage, authorization, and workflow issues.

---

## Description
Improve the application so that uploaded vehicle photos and documents display their actual image content instead of only showing file names or storage paths. Resolve the reported row-level security and authorization errors affecting customers, the Head Accountant, and the CEO approval workflow. Stabilize the Create Field Case modal and improve the organization and usability of its transaction and vehicle selection fields. Ensure that the Account Manager can access and complete the create walk-in process.

---

## Primary Objective
Fix the reported image-display, permission, approval, modal, dropdown, and workflow-access issues across the vehicle, customer, transaction, document, accounting, CEO, field case, and account management features.

---

## Secondary Objectives
- Display actual uploaded images in Vehicle Photos & Condition, the transaction page, and documents.
- Resolve the customer error that prevents saving viewing arrangements.
- Allow the Head Accountant to upload documents without receiving a “Not authorized” error.
- Enable the CEO to approve records after the required documents have been verified.
- Fix Create Field Case modal behavior and improve its transaction and vehicle dropdowns.
- Make the create walk-in process available to the Account Manager.

---

## Success Criteria
- Vehicle Photos & Condition displays the actual attached image rather than only a file name or private-storage path.
- Images are visibly rendered on the transaction page and in documents.
- Customers can click **Save Details** without receiving a row-level security policy error for `viewing_arrangements`.
- The Head Accountant can upload documents successfully without receiving a “Not authorized” message.
- The CEO approval flow works after two valid IDs and proof of billing have been verified by the Head Accountant.
- The Create Field Case modal remains open when fields are selected or interacted with.
- Transaction and vehicle data in Create Field Case are organized in scrollable dropdowns that do not cover the screen.
- The Account Manager can locate and use the create walk-in process.

---

## Context & Dependencies
- The reported issues affect Vehicle Photos & Condition, customer viewing arrangements, the transaction page, documents, Head Accountant document uploads, CEO approvals, Create Field Case, and the Account Manager workflow.
- The CEO approval process depends on the Head Accountant verifying two valid IDs and one proof of billing before approval.
- The customer save operation interacts with the `viewing_arrangements` table and its row-level security policy.
- Uploaded files are stored in private storage and currently appear as file names or storage paths instead of rendered images.

---

## Stakeholders
- Customer
- Head Accountant
- CEO
- Account Manager

---

## Supporting Tasks

### Image Rendering
- Update Vehicle Photos & Condition so attached image files are rendered as visible images rather than displayed only as file names or private-storage paths.
- Update the transaction page to display the actual uploaded images.
- Update the documents area to display actual image content instead of text references.

### Permissions and Data Access
- Investigate and resolve the row-level security error for `viewing_arrangements` that occurs when a customer saves details.
- Correct the authorization issue preventing the Head Accountant from uploading documents.
- Verify that the necessary document access and permissions support the CEO approval workflow.

### CEO Approval Workflow
- Ensure the CEO can approve a record after the Head Accountant has verified two valid IDs and a proof of billing.
- Preserve the requirement that all specified documents must be verified before approval.

### Create Field Case
- Fix the modal so that clicking or selecting fields does not unexpectedly close it.
- Organize the transaction data in the selection dropdown.
- Organize the vehicle data in the selection dropdown.
- Make the transaction and vehicle dropdowns scrollable so large data sets do not cover the screen.

### Account Manager Walk-In Flow
- Locate or add the create walk-in process for the Account Manager.
- Ensure the Account Manager can access and complete the process.

---

## Detailed Breakdown

### Uploaded Image Visibility
Replace text-only file references with rendered image content wherever vehicle photos or document images are shown. The display should use the uploaded files from private storage while preserving the existing attachment references and ensuring the actual image is visible in Vehicle Photos & Condition, the transaction page, and documents.

### Authorization and Verification Dependencies
Resolve the permissions required for customers to save viewing arrangements and for the Head Accountant to upload documents. The CEO approval flow must recognize the required verification state: two verified valid IDs and one verified proof of billing completed by the Head Accountant.

### Create Field Case Modal and Selection Controls
Correct the Create Field Case interaction so field selection does not close the dialog or modal unexpectedly. Organize transaction and vehicle data within their respective dropdowns and constrain the dropdowns with scrolling so that extensive data remains usable without covering the screen.

### Account Manager Workflow
Make the create walk-in process discoverable and accessible from the Account Manager experience, ensuring that the intended walk-in creation flow can be initiated and completed.
