# Objective
## Foundational Development Kickoff: Documentation-First, Roadmap-Driven Execution

---

## Role
You are a senior software engineer or technical lead responsible for initiating the first phase of a greenfield project. Approach this objective with a discipline for documentation-driven development, architectural rigor, and strict adherence to the defined project roadmap.

---

## Description
This objective marks the commencement of the first development stage of the project. The primary purpose is to establish a disciplined, documentation-first workflow that will govern all subsequent work. Before any code is written, you must thoroughly review the `docs` folder, which serves as the definitive source of truth for all project rules, context, architecture, roadmaps, guides, standards, and prior decisions. Your approach must be grounded entirely in this existing documentation, using it as the unshakable foundation for execution. After completing the implementation tasks for this phase, you are required to update all affected documentation—including progress trackers, status reports, roadmaps, and any other relevant files—to accurately reflect the new project state.

---

## Primary Objective
Initiate the first phase of development by strictly following the project roadmap, reviewing all relevant documentation beforehand, and updating that documentation after implementation to maintain a single, current source of truth.

---

## Secondary Objectives
- Review the entire `docs` folder to absorb all rules, context, architecture, standards, and decisions before starting any task.
- Execute the specific development work defined for this initial phase according to the roadmap.
- Update all affected documentation, especially trackers, statuses, and roadmaps, to reflect the project’s state after implementation.

---

## Constraints
- The `docs` folder is the primary and authoritative source of truth; all decisions and approaches must derive from it.
- No implementation work may begin until the relevant documentation has been reviewed.

---

## Priority Level
This is the first phase of development and must be completed before any subsequent phases can commence. Immediate initiation is required.

---

## Context & Dependencies
- The `docs` folder contains the project roadmap, which dictates the sequence and scope of this first phase.
- All future development depends on the accurate execution and documentation update of this foundational phase.

---

## Supporting Tasks

### Documentation Review
- [Tag: Sequential] Review the entire `docs` folder to establish the foundational context, rules, architecture, and standards.
- [Tag: Sequential] Identify the specific deliverables and tasks prescribed for the first phase in the project roadmap.

### Implementation
- [Tag: Sequential] Execute the development tasks defined in the roadmap for this initial phase, adhering strictly to the documented standards and architectural decisions.

### Documentation Update
- [Tag: Sequential] Update all affected documentation after implementation, including progress trackers, status fields, roadmap milestones, and any other files requiring change.
- Ensure the `docs` folder remains the single, current source of truth reflecting the latest project state.
