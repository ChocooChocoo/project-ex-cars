# Objective
## Comprehensive Audit and Review of System User Levels Against Capstone Documentation

---

## Role

You are a system auditor and requirements analyst with expertise in educational capstone project documentation, user role analysis, and system architecture validation. Approach this objective with a focus on comparing implemented user role functionalities against documented specifications, identifying alignment and discrepancies, and documenting the true purpose and scenario of each user level.

---

## Description

Conduct a thorough audit and review of all user levels defined in the system against the capstone documentation located in the docs/DOCUMENTS folder. This review focuses on understanding the documented user roles, their intended purposes, access levels, and communication flows between different user types. The analysis will compare documented user specifications against the implemented system features to identify any gaps or inconsistencies. The primary goal is to produce a comprehensive markdown document that clearly articulates the actual purpose of each user, their real-world scenario, what access they have, and how they communicate and interact with other user levels within the system.

---

## Primary Objective

Audit and review all user levels against the capstone documentation in docs/DOCUMENTS, comparing documented specifications with implemented system features, and produce a detailed markdown report that captures the actual purpose, access levels, and communication patterns of each user role.

---

## Secondary Objectives

- Identify all user roles documented in the capstone documentation
- Verify which user roles are currently implemented in the system
- Compare documented access levels and permissions against implemented features
- Document the real-world scenario and purpose of each user role
- Map communication flows and interactions between different user levels
- Identify any gaps, discrepancies, or inconsistencies between documentation and implementation
- Provide recommendations for alignment where needed

- Detailed comparison matrix showing documented vs. implemented features per user role
- Comprehensive markdown report describing each user's purpose, access, and communication patterns
- Identification of all discrepancies between documentation and implementation
- Actionable recommendations for resolving any gaps

## Detailed Breakdown

### User Role Identification Process
Begin by systematically reviewing all capstone documentation in the docs/DOCUMENTS folder. This includes reading through requirement documents, use case specifications, system design documents, and any other relevant materials. Extract all references to user roles, noting their names, descriptions, intended purposes, and any specified access levels or permissions. Create an initial inventory of all documented user roles.

### Documented Role Specifications Analysis
For each identified user role, analyze the documentation to understand:
- The role's name and classification
- The intended purpose and business function
- Specific access levels, permissions, and privileges
- Responsibilities and tasks assigned to the role
- Interaction patterns with other user roles
- The real-world scenario or use case the role represents
- Authentication and authorization requirements

### System Implementation Review
Review the actual system implementation to identify all user roles that have been created and are functional. This includes examining user management systems, authentication mechanisms, role-based access controls, and any permission configurations. Document the current state of implementation for each role, including which documented features have been implemented and which may be missing.

### Comparison and Gap Analysis
Create a detailed comparison matrix that maps documented requirements against implemented features for each user role. This will highlight:
- Roles that are fully implemented as documented
- Roles that are partially implemented
- Roles that are documented but not yet implemented
- Roles that exist in implementation but are not documented
- Features or permissions that exist in documentation but are missing in implementation
- Additional features in implementation not specified in documentation

### Communication Flow Mapping
Analyze and document how different user roles communicate and interact within the system. This includes:
- Direct communication channels between specific user roles
- Workflow interactions and dependencies
- Information flow and data sharing patterns
- Approval processes and escalation paths
- Collaboration scenarios involving multiple user roles

### Report Structure and Content
The markdown report should be organized for easy reference and comprehension:

#### Executive Summary
Brief overview of the audit findings, including the number of user roles identified, overall alignment assessment, and key recommendations.

#### User Role Inventory
Complete list of all documented user roles with brief descriptions.

#### Detailed Role Analysis
For each user role, provide:
- **Purpose**: The intended function and business value
- **Real-World Scenario**: Context and use case description
- **Access Level**: Permissions, privileges, and restricted areas
- **Responsibilities**: Tasks and duties assigned
- **Communication Patterns**: Interactions with other user levels
- **Documented vs. Implemented**: Comparison of specifications against actual system
- **Discrepancies**: Any gaps or inconsistencies identified

#### Communication Flow Diagrams
Visual representations or detailed descriptions of how user levels interact, including:
- Permission hierarchies
- Approval workflows
- Data sharing relationships
- Collaboration patterns

#### Gap Analysis Summary
Consolidated view of all identified discrepancies, organized by priority and impact.

#### Recommendations
Actionable suggestions for aligning implementation with documentation or updating documentation to reflect actual implementation.

### Documentation Update Plan
After the audit, recommend updates to affected documentation to reflect the current state of the system or to guide future implementation work. This includes:
- Updating user role descriptions where they differ from implementation
- Noting any gaps that need to be addressed
- Creating a roadmap for resolving discrepancies

## Deliverable Format

The final output should be a well-structured markdown file containing:

1. **Overview Section**: Explanation of the audit purpose and methodology

2. **User Role Matrix**: Comprehensive table comparing documented vs. implemented user roles

3. **Detailed Role Profiles**: In-depth descriptions of each user role including:
   - Role Name and Classification
   - Purpose and Business Context
   - Access Levels and Permissions
   - Responsibilities and Tasks
   - Communication with Other Roles
   - Real-World Scenario Description
   - Implementation Status

4. **Gap Analysis**: Documented discrepancies and their impact

5. **Communication Flow Documentation**: Detailed description of interactions and workflows between user levels

6. **Recommendations**: Action items for aligning documentation and implementation
