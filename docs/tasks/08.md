# Objective
## Implement Phase 5 — Transactions Can Be Followed

---

## Role
You are a full-stack developer building a multi-path transaction management system for a vehicle sales platform. Approach this objective with a focus on shared state machines, database schema fidelity, strict use of existing design system components, and documentation-driven development.

---

## Description
This phase introduces a complete transaction management system supporting three distinct transaction paths: Buy, Sell, and Request-a-Car, each with its own workflow. A shared set of transaction states must be applied consistently across all three paths to ensure unified tracking and status management. The implementation includes purchase history records, payment records, installment tracking, and sales paperwork generation, along with support for flexible payment terms. All user interfaces must be constructed using the existing shadcn template patterns located in the template folder; no custom designs are permitted. The work begins with a review of the project documentation, proceeds through database implementation using the schemas defined in the documentation, continues through UI construction, and concludes with a comprehensive update of all affected trackers and guides.

---

## Primary Objective
Implement Phase 5 transaction management features covering Buy, Sell, and Request-a-Car paths with shared transaction states, payment tracking, installment support, and sales paperwork, built on the documented database schema and shadcn UI patterns, while updating all affected documentation upon completion.

---

## Secondary Objectives
- Build the three transaction paths: Buy (R-15), Sell (R-16), and Request-a-Car (R-17), each with its own distinct workflow.
- Apply shared transaction states consistently across all three transaction paths (R-18) to enable unified tracking and status management.
- Add purchase history, payment records, installment tracking, and sales paperwork functionality (R-19).
- Support flexible payment terms that accommodate varying customer arrangements (R-37).

---

## Success Criteria
- Buy, Sell, and Request-a-Car transaction paths are fully functional with distinct workflows.
- Shared transaction states are applied consistently across all three paths.
- Purchase history is viewable and complete for all transactions.
- Payment records are created and retrievable for each transaction.
- Installment tracking accurately reflects payment schedules and statuses.
- Sales paperwork is generated and accessible for completed transactions.
- Flexible payment terms are supported and configurable per transaction.
