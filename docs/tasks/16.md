# Objective
## Align CEO and Customer Inquiry Page UI/UX and Resolve Inquiry Display Issues

---

## Role
You are a UI/UX Developer and Frontend Engineer responsible for diagnosing layout inconsistencies, investigating functional errors, and implementing fixes to ensure a cohesive user experience across user roles.

---

## Description
The objective is to investigate and resolve discrepancies between the CEO inquiry page and the customer inquiry page, which currently exhibit different layouts. The goal is to analyze both interfaces, identify the root causes of the visual mismatch, and implement corrections to achieve a consistent UI/UX design across both roles. Additionally, the investigation must address persistent placeholder messages—specifically, "Select a conversation to view messages." and "Inquiry not found."—by diagnosing the underlying functional issues that trigger these displays and ensuring that the inquiry viewing functionality operates correctly.

---

## Primary Objective
Align the layout and UI/UX of the CEO inquiry page with the customer inquiry page, and resolve the functional issues causing the persistent display of "Select a conversation to view messages." and "Inquiry not found." messages.

---

## Secondary Objectives
- Investigate the root causes of the layout mismatch between the CEO and customer inquiry pages.
- Diagnose the functional problems that lead to the "Select a conversation to view messages." and "Inquiry not found." messages.
- Implement fixes to ensure both visual consistency and proper inquiry display functionality.

---

## Success Criteria
- The CEO inquiry page layout is visually and functionally consistent with the customer inquiry page.
- The messages "Select a conversation to view messages." and "Inquiry not found." no longer appear erroneously; inquiries and conversations load and display as expected.

---

## Supporting Tasks

### Investigation and Diagnosis
- [Sequential] Compare the CEO and customer inquiry page layouts side-by-side to identify specific UI discrepancies.
- [Sequential] Review the codebase and data-fetching logic for both inquiry pages to pinpoint why the layout differs.
- [Sequential] Trace the conditions that trigger the "Select a conversation to view messages." and "Inquiry not found." messages to determine whether they are caused by data retrieval errors, state management issues, or incorrect conditional rendering.

### Implementation and Fixes
- [Sequential] Refactor the CEO inquiry page layout to match the customer inquiry page structure, ensuring consistent styling, component hierarchy, and responsive behavior.
- [Sequential] Debug and correct the inquiry data-fetching and state-update processes to ensure that conversations and inquiries are properly loaded and displayed.
- [Sequential] Update conditional rendering logic to accurately show placeholder messages only when appropriate (e.g., when no conversations exist, not due to errors).

---

## Detailed Breakdown

### Layout Discrepancy Analysis
The CEO and customer inquiry pages are expected to share a unified design system. However, the CEO page currently deviates from the customer page layout, indicating possible differences in component usage, styling overrides, or data structure handling. The investigation should begin by mapping out each page's component tree and comparing the rendered output. The fix should prioritize reusing shared UI components and applying consistent styling rules, ensuring that both pages follow the same grid, spacing, typography, and interaction patterns.

### Functional Issues with Inquiry and Conversation Display
The persistent placeholder messages suggest that the application is failing to load the correct inquiry or conversation data. This could be due to incorrect API endpoints, mismatched user role permissions affecting data queries, or client-side state management errors (e.g., incorrect initial state, failure to update after data fetch). The investigation must trace the full data flow—from API request to state update to UI render—to identify where the breakdown occurs. The fix should ensure that inquiries are correctly retrieved based on the user's role and that the conversation view updates appropriately upon selection, eliminating erroneous fallback messages.

#### Nested Details
- **Edge Cases**: Verify that the fix handles scenarios where a user has no inquiries or no conversations, ensuring that placeholder messages are shown only in those legitimate empty states rather than due to errors.
- **State Synchronization**: Confirm that the selected conversation state and inquiry list state remain synchronized after data updates or user actions to prevent display mismatches.
