# Objective
## Create an Implementation Plan for Phase 6 — Staff and Managers Can Run the Business

---

## Role
You are a technical project lead and systems architect responsible for producing a detailed implementation plan. Approach this objective with a mindset of thorough dependency analysis, gap identification, and phased planning rooted entirely in the project documentation.

---

## Description
This task requires producing a comprehensive implementation plan file for Phase 6, which enables staff and managers to operate the business using the platform. Before any Phase 6 planning begins, a full audit of the recently completed Phases 1 through 5 must be conducted against the project documentation to identify any broken functionality, incomplete features, or deviations from the documented specifications. All identified issues must be documented as prerequisite fixes. The plan itself must be derived strictly from the `docs/` folder as the source of truth and must account for all Phase 6 requirements, dependencies, database schemas, and UI patterns found in the documentation. No code implementation is required; the deliverable is the plan file only.

---

## Primary Objective
Produce a detailed Phase 6 implementation plan file that begins with a documented audit and fix list for broken or incomplete items from Phases 1 through 5, followed by a complete implementation roadmap for Phase 6, all grounded in the project documentation as the sole source of truth.

---

## Secondary Objectives
- Review the `docs/` folder thoroughly as the foundation for all planning and auditing.
- Audit Phases 1 through 5 against the documentation to identify broken, missing, or incomplete features.
- Document all prerequisite fixes required before Phase 6 work can begin.
- Define the full scope of Phase 6 features and capabilities as described in the documentation.
- Map all Phase 6 database tables, UI components, and dependencies to their documented specifications.
- Structure the plan with clear task groupings, sequencing, and success criteria.

---

## Success Criteria
- A complete implementation plan file is produced and ready for review.
- The plan opens with a clear audit section listing all identified issues from Phases 1 through 5, each referenced to specific documentation sections.
- A prerequisite fix list is included, prioritized and sequenced before any Phase 6 work.
- The Phase 6 implementation roadmap is detailed, covering all features, database changes, UI work, and documentation updates.
- All plan items reference the relevant sections of the `docs/` folder, including database schemas, roadmaps, and task trackers.
- The plan accounts for the shadcn template folder as the basis for all UI design.

---

## Constraints
- The `docs/` folder is the primary source of truth for all project rules, context, architecture, roadmaps, guides, standards, and decisions.
- All UI planning must reference the existing shadcn template folder; no custom design approaches are permitted.
- The deliverable is a plan file only; no code implementation is to be performed.

---

## Context & Dependencies
- Phases 1 through 5 have been implemented, covering authentication, vehicles, chat, recommendations, and transactions.
- Phase 6 represents the operational management layer enabling staff and managers to run the business.
- Existing database schemas, roadmaps, task trackers, and architectural decisions are documented in the `docs/` folder.
- The shadcn template folder contains the design system components to be used for all UI planning.

---

## Supporting Tasks

### Pre-Planning Documentation Review
- Review the entire `docs/` folder, treating it as the primary source of truth for all project rules, context, architecture, roadmaps, guides, standards, and decisions.
- Review the shadcn template folder to understand all available layouts, widgets, and UI elements available for Phase 6 features.

### Phase 1–5 Audit
- Audit Phase 1 against documentation for broken or incomplete items.
- Audit Phase 2 against documentation for broken or incomplete items.
- Audit Phase 3 against documentation for broken or incomplete items.
- Audit Phase 4 against documentation for broken or incomplete items.
- Audit Phase 5 against documentation for broken or incomplete items.
- Compile all findings into a documented issue list with references to the relevant documentation sections.

### Prerequisite Fix Plan
- Prioritize all identified issues from the Phase 1–5 audit.
- Sequence the fixes in a logical order that resolves dependencies before Phase 6 work begins.
- Document each fix with the affected feature, documentation reference, and expected resolution.

### Phase 6 Scope Definition
- Extract all Phase 6 requirements, features, and capabilities from the documentation.
- Identify all Phase 6 database tables, schemas, and relationships from the documented schema files.
- Map Phase 6 features to the required UI components from the shadcn template folder.
- Define task groupings, sequencing, dependencies, and success criteria for the full Phase 6 implementation.

### Plan Assembly
- Assemble the complete implementation plan file with the audit section, prerequisite fix list, and Phase 6 roadmap.
- Include references to documentation, database schemas, UI templates, and update requirements for trackers and roadmaps.
- Ensure the plan is actionable, clearly structured, and ready for handoff.

### Documentation Update
- Update all affected documentation, especially trackers, statuses, and roadmaps, to reflect the creation of the Phase 6 implementation plan.
