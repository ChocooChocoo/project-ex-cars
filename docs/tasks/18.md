# Objective
## CEO Portal Staff Management — Staff Records and Attendance Improvements

---

## Role

You are a full-stack application developer responsible for improving the CEO Portal’s Staff Management interface and attendance workflow while maintaining consistency with the existing codebase and reusable UI components.

---

## Description

Improve the CEO Portal’s Staff Management section, specifically the `ceo/staff-records` and `ceo/attendance` pages. The Staff Records page should use the existing reusable DataTable component and provide compact row actions through an icon-triggered context menu rather than multiple visible action buttons. Editing or changing a staff member’s status must use a right-side drawer instead of a modal or dialog. The Attendance page should also use the reusable DataTable while displaying real-time attendance information, enforcing schedule-based grace-period logic, handling approved leave restrictions, and presenting attendance statuses with clear semantic badge colors.

---

## Primary Objective

Improve the CEO Staff Management experience by standardizing Staff Records and Attendance around the existing reusable DataTable while implementing compact actions, drawer-based editing, real-time attendance behavior, schedule-aware late detection, approved-leave restrictions, and semantic attendance status indicators.

---

## Secondary Objectives

- Refactor `ceo/staff-records` to use the reusable DataTable component already available in the codebase.
- Replace multiple visible row action buttons with a single icon button that opens a context menu.
- Replace modal/dialog-based staff editing and status management with a right-side drawer.
- Display the current real-time clock prominently on `ceo/attendance`.
- Ensure employee clock-in and clock-out behavior follows each employee’s assigned schedule.
- Apply a configurable grace period of approximately 5–10 minutes before an employee is considered late.
- Prevent employees with an approved leave request from clocking in during the applicable leave period.
- Use meaningful badge colors for attendance statuses rather than relying only on primary or outline styling.
- Refactor the Attendance table to use the same reusable DataTable pattern used elsewhere in the codebase.

---

## Success Criteria

- `ceo/staff-records` uses the existing reusable DataTable component from the codebase.
- Staff-record rows expose actions through a compact icon-triggered context menu instead of multiple visible action buttons.
- Selecting Edit or Set Status opens a drawer from the right side rather than a modal or dialog.
- `ceo/attendance` displays the actual current time and keeps the displayed time current.
- Clock-in and clock-out behavior evaluates employees against their assigned schedules.
- Employees are not immediately classified as late while still within the configured 5–10 minute grace period.
- Employees exceeding the allowed grace period are correctly represented as late.
- Employees with approved leave for the relevant period cannot clock in while that leave restriction applies.
- Attendance statuses use distinct semantic badge treatments:
  - Present uses green.
  - Late uses a warning/yellow or yellow-orange treatment.
  - Absent uses red.
  - Leave may use an outline badge.
- The Attendance page uses the existing reusable DataTable component.
- Both tables remain visually clean and avoid unnecessary action clutter.

- Do not use a modal or dialog for Edit or Set Status interactions on Staff Records.
- Staff editing and status updates must use a right-side drawer.
- Attendance status badges must not all use the same primary or outline visual treatment.
- Approved leave must restrict clock-in during the applicable leave period.

## Detailed Breakdown

### Staff Records DataTable

The `ceo/staff-records` page should be converted to the reusable DataTable implementation already present in the project. The goal is to maintain consistency with the rest of the codebase rather than implementing a separate table pattern specifically for Staff Management. Existing reusable table capabilities should be leveraged wherever applicable.

The table should remain visually compact. Row-level management controls should not occupy several columns or display multiple buttons simultaneously.

### Staff Records Action Menu

Each staff row should expose a compact icon-based action control rather than visible Edit and Set Status buttons. Activating that icon should open a context or dropdown menu containing the available actions.

This interaction should reduce visual clutter while preserving access to staff-management operations.

### Staff Records Right-Side Drawer

Selecting Edit or Set Status must not open a modal or dialog. Instead, the corresponding interface should open as a drawer from the right side of the viewport.

The drawer should operate on the staff member selected from the DataTable and contain the appropriate Edit or Set Status interface while remaining consistent with the existing application design.

### Attendance Real-Time Clock

The `ceo/attendance` page should prominently display the actual current time because the page directly manages time-sensitive employee attendance information. The displayed clock should remain current rather than showing only a static page-load timestamp.

### Schedule-Based Attendance

Clock-in and clock-out behavior must respect each employee’s assigned work schedule. Attendance status should therefore be determined relative to the employee’s expected schedule rather than treating every employee against a single unrestricted clock-in time.

### Grace-Period Handling

Attendance should provide a grace period of approximately 5–10 minutes. An employee arriving within the allowed grace period should not automatically receive a Late status.

Once the allowed grace period has been exceeded relative to the employee’s scheduled start time, the attendance logic should classify the employee as Late.

### Approved Leave Restriction

Before permitting an employee to clock in, the system should determine whether that employee has an approved leave request covering the applicable period. When approved leave applies, clock-in must be disabled or locked for that employee during that leave period.

This restriction should prevent contradictory attendance states in which an employee is simultaneously treated as being on approved leave and actively clocked in.

### Attendance Status Presentation

Attendance statuses should use distinct semantic badge treatments so their meaning can be understood visually without relying solely on text.

Present should use a green badge. Late should use a warning-oriented yellow or yellow-orange badge. Absent should use a red badge. Leave may remain visually lighter and can use an outline badge treatment.

### Attendance DataTable

The Attendance listing should use the same reusable DataTable architecture requested for Staff Records. The table should remain consistent with existing reusable table patterns in the codebase while supporting the attendance-specific fields, statuses, and actions required by the page.
