# Objective

## Standardize Employee Requests and Enhance Security Duty Checks UI/UX

---

## Role

You are a UI/UX-focused frontend developer. Approach this objective with an emphasis on design-system consistency, reusable components, clear information presentation, and cohesive interaction patterns across the CEO portal.

---

## Description

Improve two pages within the CEO portal’s Staff Management section: Employee Requests and Security Duty Checks. The Employee Requests page should replace its current static or insufficiently dynamic table implementation with the system’s existing reusable Data Table component to maintain consistency across the application. The Security Duty Checks page should retain its existing functionality while improving its currently simple and repetitive card-based presentation by introducing multiple viewing options. Both pages should reuse existing system/template components and established shadcn styling rather than introducing unnecessary custom patterns or colors.

---

## Primary Objective

Improve the Employee Requests and Security Duty Checks pages by reusing the system’s existing Data Table component and enhancing their UI/UX while maintaining consistency with the overall CEO portal design system.

---

## Secondary Objectives

* Replace the current Employee Requests table with the existing reusable Data Table component.
* Apply consistent, predefined status colors to employee request statuses.
* Improve the overall UI/UX of the Security Duty Checks page without changing its underlying purpose.
* Add multiple presentation modes for Security Duty Checks, including table, list, and grid views.
* Ensure the Security Duty Checks table view uses the same reusable Data Table component already available in the system/template.

---

## Success Criteria

* The Employee Requests page uses the existing reusable Data Table component instead of its current table implementation.
* Employee overtime and schedule-change requests are presented consistently through the reusable table.
* Request statuses use the specified color mappings: approved as green, rejected as red, and pending as yellow.
* Status styling uses existing shadcn colors rather than introducing additional custom colors.
* The Security Duty Checks page has an enhanced UI/UX that reduces the repetitive feel of the existing card-only presentation.
* Security Duty Checks provides table, list, and grid viewing options.
* A segmented control or equivalent toggle allows users to switch between the available Security Duty Checks views.
* The Security Duty Checks table view uses the system’s existing reusable Data Table component.

---

## Constraints

* Reuse the existing Data Table component from the system/template rather than creating a separate table implementation.
* Maintain consistency with the existing overall system design.
* Use existing shadcn colors for status styling.
* Do not introduce additional custom status colors beyond the established design-system palette.
* Preserve the existing purpose of the Security Duty Checks page while improving its presentation.

---

## Context & Dependencies

* The Employee Requests page is located at `http://localhost:3000/ceo/employee-requestsin` within the CEO portal’s Staff Management section.
* The Employee Requests page contains live overtime and schedule-change requests.
* A reusable Data Table component already exists within the system and should be integrated into this page.
* The Security Duty Checks page is located at `http://localhost:3000/ceo/security-duty-checksnow` within the Staff Management section.
* Security Duty Checks contain before-and-after evidence associated with security shifts.
* The current Security Duty Checks interface primarily uses a card-based presentation.
* The existing system/template Data Table component is also available for the Security Duty Checks table view.

---

## Supporting Tasks

### Employee Requests

* Replace the existing Employee Requests table with the reusable Data Table component already provided by the system/template.
* Configure the Data Table to present live overtime and schedule-change requests.
* Apply status-specific styling using existing shadcn colors.
* Display approved requests using green status styling.
* Display rejected requests using red status styling.
* Display pending requests using yellow status styling.
* Keep the implementation visually consistent with other areas of the system that use the reusable Data Table.

### Security Duty Checks

* Refine the existing Security Duty Checks page to provide a more polished and less repetitive UI/UX.
* Preserve support for displaying before-and-after evidence for security shifts.
* Extend the current card-oriented presentation with multiple view modes.
* Add a segmented control or equivalent view toggle for switching between table, list, and grid views.
* Implement the table view using the existing reusable Data Table component from the system/template.
* Ensure the different views remain visually consistent with the overall CEO portal design system.

## Detailed Breakdown

### Employee Requests Data Table

The Employee Requests page should transition from its current table implementation to the reusable Data Table component already available within the system. The table should continue to represent live overtime and schedule-change requests while benefiting from the same reusable presentation pattern used elsewhere in the application. The objective is to improve consistency and make the page feel integrated with the broader system design rather than maintaining a page-specific table implementation.

### Employee Request Status Styling

Request statuses should be visually distinguishable using the existing shadcn color system. Approved requests should use green, rejected requests should use red, and pending requests should use yellow. These treatments should rely on colors already available through the established design system rather than introducing new custom colors.

### Security Duty Checks UI/UX Enhancement

The existing Security Duty Checks design is functional but currently feels simple and repetitive because of its card-focused presentation. Enhance the page while preserving its purpose of presenting before-and-after evidence for security shifts. The revised interface should provide users with alternative ways to inspect the same duty-check information without departing from the existing system design.

### Security Duty Checks View Switching

Introduce a segmented control or equivalent toggle that allows users to switch between table, list, and grid views. The different modes should provide alternative presentations of the Security Duty Checks information while remaining part of a cohesive page experience.

### Security Duty Checks Table View

The table mode must reuse the existing Data Table component from the system/template. It should not introduce a separate custom table implementation, ensuring that table behavior and presentation remain consistent with the Employee Requests page and other Data Table implementations throughout the system.
