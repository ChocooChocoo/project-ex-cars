# Objective
## Reorganize User Redirection and Folder Structure in src/app

---

## Role
You are a frontend architect specializing in Next.js application routing and folder structure organization. Approach this objective with a focus on route group conventions, maintainable directory hierarchies, and alignment with the project's existing patterns and documentation.

---

## Description
The current task is to examine how user redirection is implemented within the `src/app` directory and determine whether it follows a route group-based organization pattern. The expected structure groups all pages by user role using Next.js route groups, where each role resides in its own dedicated folder such as `(ceo)`, `(customer)`, or `(supplier)`. Within each role folder, related pages are organized into subdirectories. For example, the CEO route group should contain `dashboard/`, `vehicles/`, `content/`, and `inquiries/` as subdirectories, with the same organizational principle applied to all other role groups. If the existing implementation does not match this pattern, the structure should be reorganized to achieve this cleaner, role-based separation for improved maintainability and clarity.

---

## Primary Objective
Audit the current user redirection and folder structure in `src/app`, and if it does not already follow the pattern of role-based route groups with nested page subdirectories, reorganize it to match the specified structure.

---

## Secondary Objectives
- Review the `docs/` folder as the primary source of truth before making any structural decisions.
- Ensure all user roles have their own route group folder, such as `(ceo)`, `(customer)`, and `(supplier)`.
- Organize role-specific pages into appropriate subdirectories within each route group, following the pattern where `(ceo)` contains `dashboard/`, `vehicles/`, `content/`, and `inquiries/`, and apply the same principle to all other roles.
- Verify that all redirection logic correctly routes users to their respective role-based route groups.

---

## Success Criteria
- The `src/app` directory contains role-based route group folders for all user types.
- The `(ceo)` route group folder contains the subdirectories `dashboard/`, `vehicles/`, `content/`, and `inquiries/`, with equivalent organizational patterns applied to all other role folders.
- User redirection logic consistently routes authenticated users to the correct route group based on their role.
- The structure follows Next.js route group conventions and uses existing patterns from the project documentation.

---

## Constraints
- The `docs/` folder is the primary source of truth for project rules, context, architecture, roadmaps, guides, standards, and decisions.
- Any UI involved in the redirection or layout must reference the existing shadcn template folder for design patterns; no custom designs are permitted.

---

## Context & Dependencies
- The application uses Next.js App Router with route group conventions in `src/app`.
- User roles including CEO, customer, and supplier are already defined within the system.
- The expected folder structure follows this example pattern for each role:
  ```
  (ceo)/
  ├── dashboard/
  ├── vehicles/
  ├── content/
  └── inquiries/
  ```
- Existing shadcn template patterns are available for any layout or UI components needed during reorganization.

---

## Supporting Tasks

### Pre-Implementation Review
- Review the `docs/` folder to understand all project rules, architecture, and standards relevant to routing and folder structure.
- Review the shadcn template folder for any layout or UI components relevant to role-based navigation or redirection.

### Audit Current Structure
- Examine the existing folder structure and redirection logic within `src/app` to determine whether role-based route groups are already in use.
- Document any deviations from the expected structure.

### Reorganize Structure
- If needed, create or restructure route group folders for each user role following the `(role)/subdirectory` convention.
- Ensure the `(ceo)` folder contains `dashboard/`, `vehicles/`, `content/`, and `inquiries/` subdirectories, and apply the same organizational principle to all other role groups.
- Update all redirection logic to ensure users land in the correct route group after authentication.

### Documentation Update
- Update all affected documentation, especially trackers, statuses, and roadmaps, to reflect the reorganized folder structure.
