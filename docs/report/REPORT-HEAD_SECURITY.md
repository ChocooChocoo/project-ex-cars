# Head Security Audit Report

> User Level: Head Security - Investigation #8

## Summary

The Head Security has access to 6 staff modules — a deliberately narrow set alongside Marketing Specialist (5) and Mechanic (5). Compared to the CEO (23 modules) or Account Manager (19), this role is focused only on personal accountability, lot awareness, and guard operations: one dashboard, one operations view for vehicles, and four staff-management channels for attendance, requests, security duty checks, and company news. This focus is correct. The Head Security's job is guard oversight and lot security — confirming duty rounds are done, staying aware of which vehicles are on the lot, keeping personal attendance and requests in order, and staying aligned with company direction — not handling money, customer sales, supplier negotiations, or HR administration. The system keeps the role on security and lot awareness while blocking sensitive finance, transaction, and people-management areas.

All 6 modules are necessary at some level; none should be removed. One is the core owned workspace (Security Duty Checks) that should stay as it is. The other five are correctly view-only or self-service. Attendance and Employee Requests are currently personal-only, which is appropriate for self-service and protects sensitive HR decisions; if guard-team oversight is intended, it would need a small scoped extension rather than full staff access.

Sidebar order is Dashboards (Default) → Operations (Vehicles) → Staff Management (Attendance, Requests, Security Checks, Announcements).

## Modules Audited

### 1. Dashboard (Default) — Dashboards

- **What it does for Head Security:** Gives a quick daily snapshot — key metrics, performance, reconditioning progress, and notifications — to see what needs attention before opening guard operations. The Head Security shares the same base dashboard as other staff; the CEO alone sees one extra Operations Overview panel, which is correct for leadership and not needed here. The Head Security's landing page after sign-in is `/dashboard`, so this is the daily starting point.
- **Necessary for Head Security?** Yes — needs one place to spot alerts or reconditioning and performance context without opening each section.
- **Workflow:** Appropriate — read-only overview with no extra steps.
- **Recommendation:** Keep — preserve as the daily starting view.

### 2. Vehicles — Operations

- **What it does for Head Security:** Shows the full vehicle inventory — stock code, make, model, year, condition, and listing state (available, reserved, sold, archived) — so Head Security can stay aware of what is on the lot to protect. This is lot-security awareness, not listing ownership. Head Security sees the same inventory as other staff but cannot create or edit listings, propose prices, publish, archive, or delete.
- **Necessary for Head Security?** Yes, for lot security awareness — needs to know which vehicles should be on the lot, which are reserved or sold and should not move, and which are tied to a field case or inspection.
- **Workflow:** Appropriate — view-only. Only Marketing Specialist can create or edit listings and upload photos or 360-views, and only the CEO can approve a price or permanently delete. Pending price proposals are visible only to the CEO, which is correct. The view is simple and does not ask Head Security to manage listings.
- **Recommendation:** Keep — keep view-only. No edit or price access needed. A small lot-focused filter such as "on-lot: available/reserved" on top would help Head Security prioritize, with the full inventory still available on drill-down. Preserve the existing Marketing-owned listing controls and CEO approval gate.

### 3. Attendance — Staff Management

- **What it does for Head Security:** Shows personal attendance history and daily clock in and clock out controls — attendance date, time in, time out, hours worked, and status (present, late, absent, etc.) with schedule and grace-minute context. Only the CEO, Account Manager and Head Accountant can confirm attendance; Head Security manages only own clock-in/out and sees only own recent records, not the attendance of guards or other staff.
- **Necessary for Head Security?** Yes, for personal accountability — Head Security must model reliable attendance and handle own schedule correctly. For guard oversight, Security Duty Checks is the primary tool, not this general attendance log.
- **Workflow:** Appropriate for self-service — clock in first, then clock out, with blocked reasons shown (off day, on leave, account not active, already clocked in). Team checking is intentionally reserved for CEO, Account Manager, and Head Accountant who confirm records before payroll.
- **Recommendation:** Keep — keep as personal attendance and clock controls. If the role is expected to monitor guard punctuality, add a small scoped view such as "my guard team today — present/late/absent/unchecked" rather than granting full staff logs. Do not give Head Security broad checking rights for all staff; that separation protects payroll accuracy. Preserve the checked-by audit trail.

### 4. Requests (Employee Requests) — Staff Management

- **What it does for Head Security:** Holds formal staff requests such as leave. Head Security can submit new requests and view own request history, but cannot approve, reject, or review other employees' requests; only the CEO and Account Manager can review requests.
- **Necessary for Head Security?** Yes, for personal requests — needs to submit leave and track own request status. For guard-team request review, the current scope does not include it.
- **Workflow:** Appropriate for self-service — submit, then wait for CEO or Account Manager to review. No extra steps for Head Security.
- **Recommendation:** Keep — keep submit and own-history access; do not add broad review permission without explicit need. If Head Security is to approve guard leave as first-line reviewer, extend review rights to include Head Security for guard-team requests only, and keep CEO and Account Manager as final reviewers for sensitive cases. Confirm with HR and Account Manager owners before changing.

### 5. Security Checks (Security Duty Checks) — Staff Management (operational in practice)

- **What it does for Head Security:** The core workspace for guard oversight. Records before-and-after evidence for each security duty with duty date, status (pending, in progress, completed), notes, before and after images, and completed timestamp. Only the CEO and Head Security can open security checks; security checks are scoped to the logged-in guard, and only Head Security can manage and complete checks, while the CEO sees all checks for oversight. Head Security can start a check for a date, upload before and after evidence photos, and mark the check complete (requires both images); the CEO views but does not manage checks.
- **Necessary for Head Security?** Yes — this is the primary responsibility. This is how Head Security proves rounds were done and the lot was checked before and after a shift.
- **Workflow:** Appropriate and well-scoped — start check → upload before image → upload after image → Complete Check. The client supports table, list, and grid views with search, status filter, duty-date filter (last 30/90 days), evidence filter (complete, missing before/after/both), sort by newest/oldest, and pagination. Completing is blocked until both images are present, and completed checks cannot be re-edited.
- **Recommendation:** Keep — preserve Head Security as the sole manager (start, upload, complete) with own-record filtering. No broader permission needed. The CEO's all-records view already provides compliance oversight. A small summary strip such as "today pending / missing evidence" on top would help Head Security reach today's work in one click, with the full list still available behind filters.

### 6. Announcements — Staff Management

- **What it does for Head Security:** Displays company-wide announcements that are published and still active (with expiry dates) — policy updates, deadlines, safety notices, or shift and lot-security instructions from leadership. Head Security reads them; only the CEO can create drafts, publish, expire, or archive. Other staff see only published items that have not expired.
- **Necessary for Head Security?** Yes, for awareness — so guard schedules, duty requirements, and lot-security priorities align with company direction, pay dates, and safety policy.
- **Workflow:** Appropriate — view-only. No creation required for this role.
- **Recommendation:** Keep — keep view-only; no publish needed for Head Security. The CEO-owned channel is correct for company-wide communication.

## Overall Recommendations

- **Keep as is:** Dashboard (daily snapshot), Vehicles (view-only inventory for lot awareness), Security Duty Checks (Head Security-owned before-and-after evidence workspace), Announcements (view-only company news)
- **Keep as self-service (with scope confirmed):** Attendance (personal clock in and clock out and own history only), Requests (submit and own history only) — Attendance and Requests remain self-service; only add guard-team views if explicitly approved, without giving broad checking rights, which correctly protects payroll and HR approvals
- **Simplify (show summary first, details on drill-down):** Consider lightweight summary strips or "my items" filters on top of Vehicles ("on-lot available/reserved"), Attendance ("today — on time/late/absent" for own record only unless guard-team scope is added), Requests ("my pending/approved"), and Security Duty Checks ("today pending / missing evidence") — all with full lists still available on drill-down. These are quality-of-life enhancements, not required simplifications; the current views are already appropriately scoped.
- **Consider for Revision/Removal:** No module is recommended for removal. All six match the Head Security scope — lot awareness, guard duty evidence, personal attendance and requests, and company awareness. Any extra module would add clutter or expose sensitive areas; any fewer would break the core job (without Security Duty Checks there is no guard oversight function; without Vehicles there is no lot context; without Attendance and Requests there is no personal accountability channel). The only revisions to consider are scoped extensions if the business decides Head Security should see guard-team attendance and leave requests: add a filtered guard-team view rather than opening full staff logs or all-employee request review. Confirm with HR, Finance, and Operations owners before widening.

## Notes

- All recommendations are suggestions only — no functionality has been removed. Controls such as Marketing Specialist-only vehicle create/edit/publish and media upload, CEO-only price approval and vehicle deletion, publish-blocked-without-approved-price, pending-proposal visibility limited to CEO, attendance checking limited to CEO, Account Manager, and Head Accountant with checked-by audit trail, employee-request review limited to CEO and Account Manager, security duty checks create and evidence upload limited to Head Security with before-and-after required and completed-at trail, and CEO-only announcement publish/expire/archive should be preserved when adding summaries or filtered team views.
- Why this narrow set is correct for Head Security vs broader roles: The CEO (23 modules) and Account Manager (19) cover finance, transactions, suppliers, field cases, and HR. Head Security (6 modules) is intentionally not given that breadth. Modules not assigned are appropriately absent: Finance, Transactions, Payroll, Payslips, and Reports belong to Finance and HR for money movement and staff cost; Suppliers and Supplier Messages belong to CEO and Account Manager for supplier onboarding and negotiation; Inquiries, Recommendations, Content, Showroom, and Roadmap belong to Sales and Marketing for customer contact, presentation, and strategy; Inspections and Field Cases belong to Mechanic and field coordinators for vehicle condition and off-site sourcing, acquisition, delivery, and recovery; Staff Records, Field Cases, Reports, Roles, and Users belong to HR and Admin for people and access management. Security does not need to see pay, customer payments, supplier negotiations, marketing content, or strategy to do its job — the narrow set limits exposure, keeps financial and HR decisions independent, and focuses Head Security on lot security and guard accountability.
