# Supabase schema port tools

Temporary. Delete in Phase 8 along with `supabase/`.

`2026_11_18_00000{1,2,3}_*.php` in `../migrations` were generated by these scripts from the final state of `supabase/migrations`. They are now ordinary migrations; edit them by hand or add new migrations. Do not regenerate over them after later phases change them.

Use the scripts to check a new Supabase migration (schema drift rule, Phase 1):

```bash
cd backend/database/supabase-port
npm install --no-save @electric-sql/pglite@0.3.14
node replay.mjs ../../../supabase/migrations .   # replays every migration into in-memory Postgres; prints FAIL lines, writes *.json here
mkdir -p gen && node gen-laravel.mjs gen         # writes the three migrations + skipped.txt for comparison
```

`replay.mjs` stubs Supabase's `auth`, `storage` and realtime objects, so it needs no Docker and no network. It writes the final columns, constraints, indexes, functions, triggers, policies, buckets and migration-inserted rows as JSON. Diff the generated PHP against the current migrations to see what a new Supabase migration adds.

Mapping rules used: UUID → `CHAR(36)` with `UUID()` default; `TIMESTAMPTZ` → `DATETIME(6)` in UTC (connection timezone `+00:00`); `JSONB` and `SMALLINT[]` → `JSON`; unbounded `NUMERIC` → `DECIMAL(12,2)`; partial unique indexes → invisible virtual discriminator column + unique key; CHECKs translated, except the ones MySQL forbids (listed in `docs/implementation-plan/laravel-mysql-migration/phase-2.md`).
